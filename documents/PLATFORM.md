# SOD 平台化战略（PLATFORM）

> 本文回答「平台化终局是什么、怎么一步步走到」。与 `SOD.md` 的关系：`SOD.md` 的「本质」章节（管道即资产、基础设施型）在平台模式下**不变且更强**，本文不推翻它，而是在其上定义终局与路径。凡与本文冲突处以本文为准（本文较新）。
>
> 缘起：2026-09-24 CEO 对用户端原型的反馈——① 应为手机端 App；② 定位平台方（类滴滴），接单制作方可以是购买了我们硬件与耗材的小商家甚至个人消费者；③ 初期我们自己投资在试点地区扮演接单商家。

---

## 1. 终局定位

**SOD = 消费端创作平台 + 分布式微产能履约网络。**

- **消费端**（App + Web 双端并存）：用户上传「我在乎的东西」，低门槛创作、按张下单、无起订、无硬件要求。
- **履约端**：订单由平台中央拼版后，派发给分布式「微产能」节点——购买 SOD 商家套件的小商家与重度个人用户——就近打印、模切、包装、送达。

### 派单粒度：整单派发原则

> **一笔订单默认由单一商家完整履约**——打印、模切、包装、发货一气呵成，用户收到**一个包裹**。

- **中央拼版 ≠ 拆单**：拼版发生在文件层（平台把用户设计统一转成标准打印文件包下发），目的是品控一致 + 把商家门槛降到「接单即打印、无需懂排版」。派发以订单为单位，文件包整包给到接单商家。
- **不拆单的理由**：拆单 = 多包裹 + 多次物流 + 体验割裂，对低客单价贴纸是灾难；且初期个人订单以小额为主（一张起订），无拆分必要。
- **唯一例外**：单笔订单张数超出单商家产能上限（如社团 / 活动类大单）——初期此类占比极小，由平台人工拆分或自营节点兜底，**不进入常态派单逻辑**。

一句话：**滴滴不拥有一辆车，SOD 终局不拥有一台打印机**；但我们拥有「任意内容 → 低成本实体贴纸」这条管道（见 `SOD.md` §本质：管道即资产）。

### 与「本质」的衔接（不推翻，只放大）

| SOD.md 原判断 | 平台化后的含义 |
|---|---|
| 管道即资产 | 管道从「自营一条线」扩展为「自营 + N 个节点」，资产更厚 |
| 基础设施型，非内容型 | 履约网络本身就是基础设施，壁垒从管道效率扩展到网络密度 |
| 无硬件投入、单张低价（对用户） | 依然成立——硬件门槛从**用户侧**转移到**商家侧**，成为商家的生产资料 |
| 实体交付是本体 | 依然成立——分布式履约让「实体交付」更快（当日达/自提），体验更强 |

**叙事自洽**：消费端「无硬件门槛」与供给侧「硬件+耗材商业模式」是同一枚硬币的两面。1500 元的 S1 从「用户障碍」变成「商家资产」。

## 2. 滴滴模式对照

| 维度 | 滴滴 | SOD |
|---|---|---|
| 双边结构 | 乘客 ↔ 司机 | 创作用户 ↔ 微产能商家 |
| 供给侧资产 | 自带车（司机个人资产） | 自购商家套件（硬件+耗材） |
| 供给侧门槛 | **演化而来**：早期≈0（存量车主），成熟期不低（租车/专门购车的职业司机） | 高（先购商家套件，后赚钱）→ **启动慢、锁定强**（耗材持续消耗，Keurig「剃须刀+刀片」） |
| 品控难点 | 服务（驾驶体验）难标准化 | **物理产品可标准化**：中央拼版统一输出打印文件，商家只执行打印+模切+包装 |
| 网络效应 | 强（同城供需实时匹配） | 中（同城密度缩短时效、摊薄配送，但非实时调度） |
| 关键差异 | 滴滴核心资产是调度算法 | SOD 核心资产是**管道（创作→拼版）+ 密度网络**。调度是管道末梢 |

> **「供给侧门槛」一行展开**：滴滴的供给门槛是**演化出来的**——补贴大战期（约 2012-2016）主力是存量私家车主，加入成本 ≈ 0，司机零沉没成本、可同时挂多家平台（多归属），平台被迫持续烧钱，供给是「租来的」；成熟期监管合规清退兼职、供给职业化，主力变为租车或专门购车跑单的职业司机，投入不小且被车租与流水锁定。**滴滴自己走完了「零门槛 → 高门槛」的演化**——零门槛供给只是冷启动过渡形态，可持续的双边平台最终都会把供给侧承诺成本做高。SOD 商家须**先购套件、后赚钱**（供给买不来只能攒，Phase 0 自营由此而来），等于跳过滴滴的烧钱阶段、直接从其成熟形态起步；且商家投入是**专用资产**（S1 + 模切只在此场景有价值，退出即报废），比职业司机的通用资产（电车可跑别家、可当私车）锁定更强。**低门槛 = 来得快走得快；高门槛 = 来得慢走不了——滴滴先用低门槛换速度再补锁定，SOD 用慢启动直接换锁定。**

**结论**：类比成立但不可照抄。滴滴式的「轻供给启动」我们没有——我们的供给侧必须先卖出去硬件。因此路线图必须有一个「自营供给」的冷启动阶段（CEO 第③点），这与滴滴早期自营车队同理。

## 3. 商业模式：三收入线

| 收入线 | 性质 | 时点 | 备注 |
|---|---|---|---|
| 硬件销售（商家套件） | 一次性 | Phase 1 起 | 打印机 + 模切 + 耗材包 + 接单资格。**兼获客工具**：套件价格即商家筛选器 |
| 耗材复购 | 持续 | Phase 1 起 | 每单履约都消耗相纸/膜，**最强锁定线 + 品控抓手**（官方耗材才允许接单） |
| 平台抽成 | 规模化 | Phase 2 起 | 按 GMV 抽佣，比例待试点数据定（参考外卖 15-25%，我们建议初期 ≤15% 让利换密度） |

**单位经济（UE）三视角**（金额需 Phase 0 实测校准，此处为框架）：

- **单订单**：收入 = 商品价 + 运费；成本 = 耗材 + 履约人力 + 配送 + 支付/渠道费 → 目标边际为正
- **单商家**：收入 = 套件毛利 + 月度耗材毛利 + 其承接订单的平台佣金；成本 = 获客 + 培训 + 支持 → 目标 N 个月回本（门槛指标见 §5）
- **平台**：收入 = Σ佣金 + Σ耗材渠道毛利；成本 = 研发 + 中央拼版算力 + 品控 + 运营 → 达到城市盈亏平衡所需订单密度

## 4. 产品矩阵：三端 + 一阶段工具

| 端 | 用户 | 形态（验证期 → 终局） | 核心能力 |
|---|---|---|---|
| **用户端** | 创作用户 | Web App（现有原型，GitHub 部署）→ App + Web 双端 | 上传/抠图/排版/下单/订单 |
| **商家端** | 微产能节点 | Phase 0 无（自营）→ 微信小程序 | 接单/打单/耗材管理/发货上报/收入提现 |
| **平台后台** | 我们自己 | Phase 0 飞书多维表格 → 代码化 | 订单池/拼版/派单/品控抽检/商家结算/数据看板 |

### 4.1 端策略：为什么 Web 先行、App 后置

- **当下（探索期）**：定义未稳，迭代速度第一。GitHub 部署 + 浏览器查看 = 零发布成本、改完即看；手机端形态用 Figma 高保真原型探索。
- **终局**：App + Web 并存（CEO 定调）。用户照片在手机、灵感即时、分享即社交——App 是主战场，Web 承接桌面创作与流量落地。
- **技术约束（对开发的要求）**：编辑器核心逻辑（画布模型/抠图调用/拼版数据结构）与 UI 框架解耦，确保后续切 App（原生或 RN/Flutter）时核心可复用，不推倒重写。
- **商家端做微信小程序而非 App**：小商家活在微信生态（接单通知、客服、收款都在微信），且接单-打单-上报的操作复杂度撑不起独立 App 的分发成本。

### 4.2 自研 vs 购买（回答「pilot 阶段自己开发还是买现成」）

**原则：差异化环节自研，通用环节用现成，验证阶段两个都不建。**

| 能力 | Phase 0（试点） | 归属与理由 |
|---|---|---|
| 订单管理/打单/发货 | **飞书多维表格**人工跑单 | 验证目标是学需求，不是建系统。Uber 前 1000 单是创始人手动派单 |
| 拼版引擎 | 自营直接用 SOD 编辑器导出 | **核心资产，必须自研**——「任意内容→打印文件」的管道本体 |
| 派单/品控/商家结算 | 人工（表格+对账） | Phase 1 代码化，逻辑先在表格里跑通再固化 |
| 支付 | 微信支付（现成） | 通用基础设施，绝不自造 |
| 物流对接 | 快递100/快递鸟 API（现成） | 通用 |
| 客服 | 企微/微信群 | 通用 |

**为什么不买现成后台系统**：市面上不存在「按需贴纸生产调度」的垂直方案——电商 SaaS 是店铺逻辑、外卖 SaaS 是餐饮逻辑，均无法表达「中央拼版 + 模切工艺 + 耗材绑定」；而拼版与派单恰是我们的差异化本体（管道即资产），**能买到的都不是壁垒**。可购买部分（支付/物流/客服）全部用现成。

**从表格到代码的切换信号**（Phase 0 → Phase 1）：人工跑单开始丢件/错单（质量信号）、或日均单量 > 30（效率信号）、或商家数 > 3（协作信号）——三条满足其一即启动后台代码化。

## 5. 三阶段路线图

> 每阶段定义：目标 / 关键动作 / **门槛指标（gate，达标才进下一阶段）** / 退出-转向条件（不达标怎么办）。

### Phase 0：自营试点（验证需求与单位经济）

**目标**：在 1 个试点城市，以自营微产能跑通「创作→下单→拼版→打印→模切→包装→配送」全链路，验证需求真实性与 UE 框架，并**以商家视角记录每一单的成本与耗时**（这份账本就是 Phase 1 商家招募的核心素材）。

**关键动作**：
1. Web App（现有原型演进）上线试点，限定单城市；
2. 自营微产能节点：购入 S1（或其商家版配置）+ 模切 + 耗材库存，选址（办公场地一角即可，无需门店）；
3. 飞书多维表格搭建跑单系统：订单池 → 拼版状态 → 打印 → 发货 → 对账；
4. 定价与优惠券按 `SOD.md` 现行方案试运行，实测真实转化;
5. 每单记录：耗材成本、人力分钟数、配送费、客诉/退货。

**门槛指标（Gate 0，建议值，上线 8-12 周内达标）**：
- 周订单 ≥ 100（需求真实）
- 创作→下单转化 ≥ 8%（体验成立）
- 30 日复购率 ≥ 15%（黏性成立）
- 单均 UE 边际 ≥ 0（自营都不赚钱，外包更不可能）
- 全链路 SOP 文档化完成（可复制给外部商家的成熟度）

**退出/转向条件**：周订单 < 40 且两轮迭代无效 → 回到获客与定价层重审（问题大概率不在履约）；转化达标但复购 < 8% → 审「悦己一次性」风险，考虑订阅制/会员方向再试。

### Phase 1：供给扩张（自营为主 + 首批外部商家）

**目标**：把 Phase 0 的 SOP 卖给第一批外部微产能——**首要目标池：S1 存量个人用户中已表现出的重度使用者**（他们就是 CEO 说的「甚至其他个人消费者」，滴滴的「司机」其实早已入场）。

**关键动作**：
1. 定义并定价**商家套件**（硬件 + 首批耗材 + 接单资格 + 培训）；
2. 商家端微信小程序 MVP：接单推送、打印文件下载、发货上报、收入账单；
3. 平台后台代码化（触发信号见 §4.2）：中央拼版自动下发 + 简单派单（按地理就近 + 商家评分）+ 品控抽检流程 + 商家结算；
4. 自营节点继续运行，作为**标杆与兜底**（外部商家爆单/异常时接住）；
5. 品控三板斧：中央拼版保输出一致 / 官方耗材绑定（非官方耗材不派单）/ 首单强制人工抽检 + 用户评价回流派单权重。

**门槛指标（Gate 1，建议值）**：
- 外部商家 ≥ 5 家在网，月均在网时长 ≥ 90%
- 外部商家订单质量达标率（无退款无差评）≥ 92%
- 商家月均增收 ≥ 1,500 元（值得干的副业/主业信号）
- 商家套件回本周期 ≤ 6 个月（可讲给下一个商家的故事）
- 配送时效：试点城市当日达占比 ≥ 60%（分布式履约的价值证明）

**退出/转向条件**：商家招募不动（<3 家/季度）→ 问题在套件定价或 SOP 成熟度，回 Phase 0 补素材而非硬推；质量达标率 < 85% → 暂停扩张，品控先行（中央拼版参数与耗材绑定收紧）。

### Phase 2：平台飞轮（自营转标杆，密度换盈利）

**目标**：收入结构从自营订单转向「耗材 + 佣金」，验证城市复制模型。

**关键动作**：
1. 自营节点转为标杆店/培训基地，日常订单全部外放；
2. 城市扩张 playbook：单城微产能密度模型（每 X 单/日需 1 节点）→ 选城 → 复制 Phase 1；
3. 佣金体系上线（初期 ≤15% 让利换密度）；
4. 数据复利：作品库/审美偏好/创作习惯反哺编辑器与获客（`SOD.md` §两条长线判断的第二条）；
5. 商家分层：普通 → 认证 → 金牌，派单权重与培训体系挂钩。

**门槛指标（Gate 2）**：单城佣金+耗材毛利覆盖该城全部运营成本（单城 UE 转正）；≥3 城复制成功；商家 NPS ≥ 40。

**退出/转向条件**：单城模型 6 个月无法转正 → 收缩回优势城市做深，等待硬件成本曲线下降（S1 降价或轻量商家机推出）再扩。

### 时间轴（概览）

```
2026 Q4        2027 Q1-Q2           2027 Q3+
─────Phase 0────┬────Phase 1─────────┬────Phase 2─────
自营试点(1城)    │ 供给扩张(5-10商家)   │ 平台飞轮(多城)
Web App 演进    │ 商家小程序+后台代码化 │ 佣金+城市复制
飞书表格跑单     │ S1存量用户转化商家    │ 自营转标杆
Gate 0 验证     │ Gate 1 验证         │ Gate 2 验证
```

## 6. 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| **冷启动死循环**（无商家→时效差→无用户→无商家） | 高 | 这正是三阶段存在的意义：Phase 0 自营消灭「先有鸡还是先有蛋」，用自营供给把体验做出来再放商家 |
| 品控崩坏（外部商家输出参差） | 高 | 中央拼版（文件级统一）+ 耗材绑定 + 抽检三板斧；品控不达标不扩张（Gate 1 硬约束） |
| 商家不赚钱流失 | 中 | Phase 0 记录的真实账本 + 回本周期承诺；自营兜底派单保底量（首批商家保护期） |
| 「悦己一次性」需求天花板 | 中 | Gate 0 复购指标前置拦截；若触发转向条件，探索订阅/会员/礼赠场景 |
| 竞对复制（硬件厂商直接做平台） | 中 | 壁垒不在硬件在管道+密度：S1 已量产说明硬件可买，但「创作→拼版→网络」管道需时积累；加速 Phase 1/2 是最好的防御 |
| 低价陷阱（单张 1 元撑不起履约成本） | 中 | Gate 0 UE 边际指标前置；分布式履约摊薄配送是结构性解法（同城并单/自提点） |

## 8. 待定项（不阻塞路线图，Phase 1 前需闭环）

- 商家套件定价（硬件补贴 or 原价 + 佣金返还？）
- 佣金比例与结算周期（T+1 / T+7？）
- 商家版硬件是否需要与消费版 S1 区分（模切能力、耗材容量、耐用性）
- 首批试点城市选择标准（现有 S1 销量密度 + 手帐/谷子文化浓度）
- 外部商家准入：个人 vs 个体工商户的法务与税务处理
